### Что сделано в этой сессии

1. **UI-выравнивание («слева пустые мета, выровняй все»)** — home.rs переписан:
   карточка до 840px, вертикальное центрирование (высота карточки меряется в
   App::home_content_h и сходится за 2 кадра), при узкой центральной области
   (<620px: открыта шторка/маленькое окно) колонки «Разрешить управление»
   складываются в один столбец, размер моно-ID масштабируется под ширину
   столбца `((col_w-26)/6.9).clamp(15,30)` — «123 456 789» НИКОГДА не
   переносится (у пользователя рассыпался на 4 строки при открытой шторке),
   поля заполняют столбец, статус левее под полями. ВЕРИФИЦИРОВАНО
   скриншотами в Xvfb (scripts/ui_align_probe.sh: 1564x1100 шторки
   Настройки/История/Контакты + 900x700 + 900x700+шторка). Кнопки верхней
   панели: Настройки ~W-242, История ~W-154, Контакты ~W-80 (y~22).
2. **Android-приложение**: новый крейт `crates/opacusr-android` (cdylib,
   `android_main` через eframe `event_loop_builder` +
   `EventLoopBuilderExtAndroid::with_android_app`; eframe 0.29.1 = winit
   0.30.5, у которого android требует явный `with_android_app`, паникует
   иначе). Манифест cargo-apk: io.opacusr.app, arm64-v8a, min SDK 24,
   target SDK 34 (на раннерах GitHub НЕТ platform 30!), полноэкранная тема.
   Телефон = зритель (те же поля ID/пароля, подключение по ID или ip:port).
   Release.yml джоба android: cargo-apk + NDK r27b (nttld/setup-ndk),
   APK публикуется ассетом; SHA256SUMS по всем файлам.
3. **Подпись APK**: cargo-apk 0.10 для release требует кейстор; в CI
   генерируется keytool'ом один раз и живёт в actions/cache
   (key: opacusr-android-release-keystore-v1) → подпись стабильна между
   релизами (обновления ставятся поверх). ПАРОЛЬ: opacusr-release-key.
   ГЛАВНЫЕ ГРАБЛИ: (a) env `CARGO_APK_RELEASE_KEYSTORE` — путь ДОЛЖЕН быть
   абсолютным (${{ github.workspace }}/release.keystore), т.к. cargo-apk
   делает `cd target/release/apk` перед apksigner; (b) член workspace НЕ
   может переопределить default-features=true workspace-зависимости —
   только выставить false в САМОЙ workspace-записи и включить фичи
   per-target. Из-за этого agent `audio` фича: workspace
   `opacusr-agent = {..., default-features = false}`, desktop-цель
   `features = ["audio"]`, mobile — без.
4. **Мобильные фиксы кода**: keychain.rs — заглушка для android/ios (та же
   сигнатура, Err «keychain unavailable», фолбэк в конфиг); input lock
   (`lock.rs`, evdev/LL-hooks) — `#[cfg(not(any(android, ios)))]` в lib.rs
   input-крейта, вызов в agent/session.rs:159 гейтирован (мобильный
   `_input_lock = ()`); ioctl EVIOCGRAB cast `as _` (тип Ioctl различается
   по архитектурам); rfd спрятан в cfg(not(android/ios)) с хелперами
   pick_file/pick_files/pick_folder в lib.rs приложения; аудио отключено
   на мобильных (client и agent без audio-фичи) — Opus под NDK позже.
5. **iOS**: CI-чек пока `cargo check -p opacusr-proto -p opacusr-crypto
   --target aarch64-apple-ios` — ПОЛНЫЙ клиент блокирован upstream:
   webrtc 0.14 → webrtc-util 0.12 → nix 0.26 (sockaddr_ctl не объявлен
   для iOS в libc). Когда webrtc поднимет nix — расширить чек и сделать
   iOS-шелл. Это НЕ наша ошибка.
6. **Сборки на Linux/macOS проверены**: локальная сборка GUI на Linux
