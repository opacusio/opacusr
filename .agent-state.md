## Proto v8 batch (2026-11-02) — `ececa3e`

- **Wayland cursor via portal** (`opacusr-capture`): the screencast session is
  now negotiated with `CursorMode::Metadata`; the worker parses each buffer's
  `spa_meta_cursor` (hotspot position + inline sprite bitmaps) into a shared
  `PwCursorState` (OnceLock global in `wayland.rs`), and `CursorPoller` picks
  `Inner::PipeWire(PwCursor)` on Linux when built with the `pipewire` feature
  inside a Wayland session. Semantics verified against PipeWire 1.0.7
  `spa/buffer/meta.h`: `id==0` = no new data, `position` = hotspot-on-screen
  (same convention as XFixes/Win32 — no translation), `bitmap.offset==0` =
  invisible sprite, `bitmap.format==0` = "no new bitmap" (position still
  applies), `bitmap_offset` <28 = garbage. Serial is OUR counter bumped when
  the converted RGBA differs from the cached bitmap (compositor-independent).
- **Byte-level parser** (`cursor_meta.rs`, no cfg, 10 unit tests): reads the
  documented C layout instead of bindgen structs → testable without a
  PipeWire build; `bitmap_to_rgba` supports BGRA/BGRx/RGBA/RGBx/ARGB/ABGR.
- **Chunked clipboard** (proto v8): `ClipboardBegin{transfer_id,kind,width,
  height,total_len,chunk_size}` + `ClipboardChunk{transfer_id,seq,data}`;
  sender splits at `CLIPBOARD_CHUNK_SIZE` (256 KiB) when text > 512 KiB or
  PNG > 6 MiB (single-message caps stay for small payloads); receiver
  reassembles via `opacusr_input::clipboard::ChunkAssembler` (order+size
  validation, 64 MiB cap `CLIPBOARD_CHUNKED_MAX_BYTES`, new `begin` replaces
  a stale transfer, UTF-8 check for text). Both directions in agent + client
  (incl. `Command::SendClipboard` going chunked for big texts).
- **Quality tier in viewer UI** (proto v8): host → viewer `QualityTier{tier
  0..=3, fps, jpeg_quality, scale_percent, enabled}` sent after
  `SessionAccept`, on every `LinkStats`-driven tier change and on manual
  `QualitySet` (`enabled=false`). Client emits `ClientEvent::QualityTier`;
  egui toolbar shows a colored badge (`⚡ best/tier 1..3`) + hover with the
  live params; stats panel gains a "Quality tier" row (adaptive / manual).
- `PROTO_VERSION` 7 → 8 (peers must match). CHANGELOG NOT YET UPDATED —

## Windows/macOS cross-check technique

```
rustup target add x86_64-pc-windows-msvc aarch64-apple-darwin
cargo clippy -p opacusr-capture --target x86_64-pc-windows-msvc --all-targets -- -D warnings
cargo clippy -p opacusr-capture --target aarch64-apple-darwin --all-targets -- -D warnings
cargo clippy -p opacusr-capture --no-default-features --all-targets -- -D warnings
```

- `cargo check/clippy` needs no linker → works for foreign targets. Limit: crates pulling `ring` (→ opacusr-transport, agent, client) need the target's C toolchain → cannot cross-check locally; CI compiles natively.
- Gotchas fixed in `92192de` (still relevant): windows-sys `HBITMAP` lives in Gdi; `RGBQUAD` has no `Default`; clippy `chunks_exact_to_as_chunks` fires only on windows path; empty `Inner` enum on macOS → cfg'd wildcard arms + cfg_attr allow(unused_variables); keep `None` arm BEFORE cfg'd `_`.

  (unit `PipeWire` vs big `X11Cursor`) → `Inner::X11(Box<X11Cursor>)`.
- New this session: with 3+ cfg'd variants, every `not(any(windows, x11, pipewire))`

## Session lessons (2026-11-02, sandbox rebuild)

- **pipewire-rs 0.8 `Buffer` exposes NO raw pointer / metas** — only
  `datas_mut()`. Workaround: element 0 of the `datas` array (via
  `Data::as_raw()`/slice base) minus the computed `offsetof(spa_buffer, datas)`
  gives the containing `spa_buffer`, whose `metas` array is then readable.
  Zeroed-struct probe computes the offset portably at runtime.
- bindgen field renames: `spa_meta.type` → `type_`; enum VALUES pinned locally
  (SPA_META_Cursor = 5 — NOT 4; the order is Invalid, Header, VideoCrop,
  VideoDamage, Bitmap, Cursor, …) with a header citation, avoiding dependency
  on bindgen constant names.
- Prioritized-summary context was stale again (described the three v0.8
  features as "not started" while v0.7.0 had shipped); **always re-read
  `.agent-state.md` + `git log` after a rebuild before trusting a summary.**
- Cold-sandbox bootstrap: rustup minimal → `rustup component add clippy
  rustfmt` → `rustup target add x86_64-pc-windows-msvc aarch64-apple-darwin`
  → `pip install libclang` → fake_alsa + fake_pipewire → source env script.
- **PAT handling: used inline per-command, never stored on disk/config, push
  via one-shot `https://x-access-token:$PAT@github.com/...` URL; outputs
  sed-masked.** Shell env vars do NOT survive between tool calls. ⚠️ Advise
  user to revoke/rotate the token (it was pasted in chat).
- **GitHub recon without a PAT** (API rate-limited per IP): badge.svg
  `actions/workflows/ci.yml/badge.svg?branch=main` → `<title>` = latest
  run status; actions/workflows/ci.yml HTML embeds
  `react-app.embeddedData` JSON with runNumber/id/conclusion/title for
  ~25 recent runs (also `?query=is:failure`); run/job DETAILS are not
  SSR — need the API+PAT. Prioritized summaries can also be stale —
  re-read `.agent-state.md` + `git fetch` first (done, saved this
  session: summary claimed the batch wasn't started while it was already
  shipped).
- **API recipes with a PAT**: rerun only failed jobs = POST
  `/actions/runs/{id}/rerun-failed-jobs` (HTTP 201; job conclusions
  reset to pending immediately — query jobs BEFORE rerunning to see
  what failed); re-runs use the workflow file from the run's HEAD
  commit (old ci.yml → old flake can recur); job logs =
  `/actions/jobs/{job_id}/logs` (only for completed attempts). A
  multi-commit `git push` creates ONE CI run for the tip SHA —
  intermediate commits get no dedicated run.
- **v0.7.0-era red runs root cause**: vendored OpenH264 aborts the
  full_session e2e on macOS ("Rust cannot catch foreign exceptions",
  SIGABRT) — with RUST_TEST_THREADS=4 it's near-deterministic on
  current runner images (#47 failed 3/3), with =1 it's a rare flake
  (#49 attempt 1). Hardened by the ci.yml "Retry tests once" step.
- `cargo fmt` reformats freshly written asserts → keep that in mind when
  patching scripts by string-match (match post-fmt text).
- e2e design: after a manual `QualitySet` the adaptive controller is OFF —
  no `QualityTier` will follow a `LinkStats` (assert the ABSENCE with a
  short negative-timeout, don't await a message that never comes).
