## Windows service batch (2026-11-02) — `90107e8`, SHIPPED

- `opacusr-agent service install|uninstall|status|run` (SCM name
  OpacusRAgent, auto-start, LocalSystem) — new
  `crates/opacusr-agent/src/win_service.rs` (524 lines) + windows
  deps in agent Cargo.toml.
- **Session-0 design: the service never captures.** Supervisor polls
  the active console session every 5 s and keeps exactly one regular
  agent child alive there — user token + environment block +
  winsta0\default desktop via WTSQueryUserToken + CreateProcessAsUserW,
  bound to a kill-on-close job object. Crash of the supervisor reaps
  the child; logoff/session switch/service stop stop it; a new logon
  respawns it. Capture/input therefore always run in the interactive
  session — the session-0 isolation problem never touches capture.
- Child runs config-only (user's own config + OS-keychain password);
  `service install` warns when no unattended password is set (no
  console for the attended consent prompt).
- Supervisor decision table `tick()` is pure and unit-tested on every
  platform (agent +6).
- **CI gains a windows-gnu cross-clippy step** (`cargo clippy -p
  opacusr-agent --target x86_64-pc-windows-gnu --no-default-features`)
  — local equivalent needs mingw in PATH (see sandbox notes).

## Session lessons (2026-11-02, sandbox rebuild)

- **pipewire-rs 0.8 `Buffer` exposes NO raw pointer / metas** — only
  `datas_mut()`. Workaround: element 0 of the `datas` array (via
  `Data::as_raw()`/slice base) minus the computed `offsetof(spa_buffer, datas)`
  gives the containing `spa_buffer`, whose `metas` array is then readable.
  Zeroed-struct probe computes the offset portably at runtime.
- bindgen field renames: `spa_meta.type` → `type_`; enum VALUES pinned locally
  (SPA_META_Cursor = 5 — NOT 4; the order is Invalid, Header, VideoCrop,
  VideoDamage, Bitmap, Cursor, …) with a header citation, avoiding dependency
