## v0.11.12 SHIPPED (tag on d0f45b4, run 45052973761 success)

Request: «Номер появился, нажимаю подключиться ни чего не происходит»
(screenshot: phone 0.11.11 registered fine — ID 417 366 579, «ID активен»
— then typed the PC ID 761081729 with an EMPTY password and tapped
«Подключиться»; nothing visible happened).

Root causes found:
1. UX: connect_clicked bails on empty password with a WEAK GRAY status
   line under the fields — on a phone it reads as nothing happening.
   (The user indeed had an empty password field in the screenshot.)
2. Architecture trap behind it: each device defaults to its OWN embedded
   signaling server (server_url = ws://127.0.0.1:8080/signal + embedded
   listener on 0.0.0.0:8080/relay 8081). Phone and PC IDs live on two
   different registries — connecting by ID across the internet CANNOT
   work until both point at one shared server (or LAN ip:port). The
   failure surfaced only as «closed: all signaling endpoints failed
   (… peer X is offline)» on the session screen, never on home.
   ALSO: the user typed 761081729 while the PC showed 716 081 729
   (transposed digits) — «проверьте ID» hint matters.
   ALSO: allow_lan (direct LAN ip:54000 sessions) was config-only —
   NOT exposed in the settings UI at all.

Fix (commit d0f45b4):
- status_is_error flag on App: connect-card status renders GOLD for
  errors (empty password «Введите пароль компьютера — без него
  подключение невозможно», invalid ID, bad proxy), weak gray otherwise.
- focus_password flag: empty-password attempt requests focus on the
  password field (keyboard up on a phone immediately).
- ClientEvent::Closed mirrors the outcome onto the home card:
  failed-looking reasons (failed/offline/timed out/timeout/rejected/
  refused/error) → friendly_connect_error() with situation hints
  (offline → check ID/agent/ONE shared signaling server + LAN ip:port
  guidance; rejected/password/auth → password/2FA hint; timeout →
  internet/server hint). Clean close → neutral «Сессия закрыта.»
  disconnect_clicked keeps the error text (no «Отключено.» overwrite).
- Настройки → Хост: new «Прямые LAN-подключения» checkbox (allow_lan),
  hint explains ip:54000 + agent restart needed.
