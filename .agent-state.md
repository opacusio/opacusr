Request: «В андроид тоже сервер не запускается, проверь все сборки»
(screenshot: Android app stuck on «Идёт регистрация на сервере…»).

ROOT CAUSE (the long-standing «регистрация на сервере» issue, Android
side):
- The cargo-apk manifest in crates/opacusr-android/Cargo.toml declared
  ZERO Android permissions. Without `android.permission.INTERNET` the
  OS refuses EVERY socket() — INCLUDING loopback — so the embedded
  signaling listener could not serve and the agent could never register.
  Windows/Linux/macOS were unaffected (desktop has no permission model).

Fix (commit 1beb22b):
- [[package.metadata.android.uses_permission]] ×2: INTERNET +
  ACCESS_NETWORK_STATE (SINGULAR key name per official cargo-apk README).
- uses_cleartext_traffic = true under [package.metadata.android.application]
  (default/LAN signaling is ws://; native sockets bypass the check, but
  future JVM-side HTTP won't be blocked on API 28+).
- All builds: home.rs «Этот компьютер» now shows host.notices.last()
  under «регистрация на сервере…» (gold) — connection failures were
  previously visible only in Настройки → Диагностика.
