## v0.11.13 SHIPPED (tag on fc62274, CI main success, release run 45057937701 success)

Request: «Пароль поставил, но вот такой экран» — screenshot showed the
0.11.12 session screen with the GOLD error «closed: all signaling endpoints
failed (ws://127.0.0.1:8080/signal: signaling error: host unavailable: peer…)».
So 0.11.12 worked as designed (error is now visible + password field is
required), but the user was stuck on the NEXT layer: the phone client was
asking its OWN embedded signaling server for the PC's ID — two devices, two
loopback registries, «host unavailable» forever.

Root causes fixed (commit fc62274):
1. Nobody tells the user WHAT address to use. The PC's LAN address and its
   embedded signaling URL were invisible (ipconfig knowledge assumed).
2. REAL BUG: the «Сигнальный сервер» field (Настройки → Подключение) was
   memory-only — never written to agent.toml; after a restart the phone
   silently reverted to loopback. That is why a configured phone would
   keep failing.
3. The field's hint LIED («по умолчанию публичный») while the default is
   the loopback embedded server.

Fix (fc62274):
- theme::lan_ipv4() — connected-UDP-socket trick (route lookup, no packets),
  None without an IPv4 default route.
- home.rs own_machine_strip: under the ID, two click-to-copy chips —
  «Wi-Fi / LAN: <ip>:<lan_port>» and «сигналинг: ws://<ip>:<signal_port>/signal»;
  loopback/custom server_url handled by pure peer_setup_hints(); extra hint
  when allow_lan is off. 4 new tests (hints + lan_ipv4 tolerant).
- settings.rs connect_tab: server_url persists on change
  (config.server_url = app.server_url; config.save()); honest hint.
- friendly_connect_error: offline branch now says WHERE the address lives
  (host card) and WHERE to put it; new branch for refused direct ip:port
  (allow_lan + agent restart + firewall).

## User-facing recipe (given in chat)

- Один Wi-Fi: ПК-карточка → скопировать IP:54000 → включить «Прямые
  LAN-подключения» (Настройки → Хост) → на телефоне вставить в поле ID.
