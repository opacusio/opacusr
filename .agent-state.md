0.11.24 (7826138, one commit):
- WINDOWS ROOT CAUSE: the p2p node was started from the egui UI thread
  via a bare `tokio::spawn` inside `opacusr_libp2p::spawn` — panics
  without a runtime context. Because «запускать узел вместе с OpacusR»

  `Handle::try_current()`, fallback to a crate-owned OnceLock runtime
  (`NODE_RT`, 1 worker, thread name opacusr-p2p) built lazily; the
  caller's runtime (p2p-node CLI under #[tokio::main], tests) is used
  when entered. GUI start_node additionally wraps the spawn in
  `catch_unwind` (Ok(Ok)/Ok(Err)/Err(panic) → status lines; app never
  dies from node startup). Regression tests in opacusr-libp2p:
  `spawn_works_without_ambient_runtime` (plain thread — the exact
  0.11.23 scenario) + `spawn_inside_runtime_uses_it` (block_on path).
  NOTE: current-thread runtime test must keep block_on alive while
  waiting (whole assert inside one block_on).
- ANDROID: p2p module was desktop-only because of an OUTDATED comment
  (aws-lc-rs "not wired for mobile") — in reality aws-lc-rs/ring were
  ALREADY compiled for aarch64-linux-android via opacusr-transport
  (webrtc/dtls → rustls) in every APK since the webrtc landing. Flipped
  cfg gates `not(any(android,ios))` → `not(ios)` in opacusr-app
  (lib.rs mod p2p; app.rs field/init/autostart/poll_events;
  settings.rs p2p_tab desktop variant + ios fallback kept) and moved
  `opacusr-libp2p` dep to a new `[target.'cfg(not(target_os="ios"))']`
  block. Same settings pane works on the phone (PeerId, invite addr,
  bootstrap, ping, events); identity file p2p_identity.key lives in
  $OPACUSR_CONFIG_DIR (android internal files dir, set in android_main
  before App::new). Verified LOCALLY with a real NDK r27b (downloaded
  from dl.google.com, ~25 MB/s): `cargo check -p opacusr-android
  --target aarch64-linux-android` green; CI mobile job green.
- Sandbox trick: alsa link for `cargo test --workspace` uses the REAL

## v0.11.23 SHIPPED (326ea3b, release run 45361082990-rerun, ALL GREEN)

User report (0.11.22 installed, screenshot): «не может остановить и
обновить службу на Windows» — MSI upgrade showed the Restart Manager
dialog «The setup was unable to automatically close all requested
applications» and refused to replace files while OpacusR was running.

0.11.23 fix (326ea3b, wix/main.wxs only + versions):
- Root cause: the RM check runs at InstallValidate BEFORE the
  transaction opens; ServiceControl Stop runs after InstallInitialize
  (too late); the per-session agent child is a console process (RM has
  no polite close for console apps); the GUI hides to the tray and
  cancels WM_CLOSE. Deferred CAs cannot run before InstallValidate
  (error 2762) — the fix must be IMMEDIATE actions.
- Fix: 8 immediate WixQuietExec (WixUtilExtension WixCA, already
  linked) actions chained before InstallValidate: setter+exec pairs
  (immediate QuietExec reads and CLEARS WixQuietExecCmdLine, so each
  command needs its own setter) — sc stop OpacusRAgent, then
  taskkill /F /T /IM opacusr.exe / opacusr-agent.exe /
  opacusr-server.exe. Return='ignore' (fresh install: taskkill=128,
  sc stop=1062). ServiceControl Start='install' restarts the service
  after file replacement; exit-dialog checkbox relaunches the GUI.
  Plain uninstall is quiet too (same actions run in all modes).
- Version alignment: workspace deps pinned 0.11.23 (crates inherit
  via version.workspace=true — they can NOT lag), MSI default
  MsiVersion 0.11.23, README-WINDOWS.txt documents the silent update
  path + fixed stale mingw claim (build is MSVC).

Verification: fmt + clippy -D warnings clean; 33 test suites ok
(145 tests). CI 45361082990: windows-latest failed once on

  history_row needs &mut App while the list is borrowed from it.
